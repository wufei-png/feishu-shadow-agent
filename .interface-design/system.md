# Operator Console 界面规范

## 使用场景与方向

面向单人值守的飞书 Shadow Agent 操作台。进入页面时，操作者首先判断哪些不确定分流、审批和受阻任务需要处理，再打开对应证据与详情。界面保持冷静、紧凑、可扫描；首页的「待我处理」决策索引是视觉和操作焦点。

界面是一条盖在运行中机器上的玻璃：**外壳是材质，你的证据是不透明的，唯一需要动手的东西是屏幕上唯一的实体**。静态界面文案使用中文；API 返回的标识符、错误码和原始内容保留原文，方便排障。

## 主题与色彩

- 主题选项为「跟随系统／浅色／深色」，在**设置 → 外观与语言**中修改。选择保存在本机；「跟随系统」响应系统配色变化。页面在应用加载前设置根元素主题，避免首屏闪烁。
- 中性石墨阶梯，只走明度、不带色相：浅色画布 `#f2f2f4`、面板 `#ffffff`、抬升层 `#f7f7f9`、内嵌 `#e8e8ec`；深色画布 `#0d0d0f`、面板 `#17171a`、抬升层 `#1f1f23`、内嵌 `#09090b`。
- 青绿是**唯一**强调色，只用于选中、焦点与成功：浅色 `#137b70`、深色 `#75d5be`。警告与危险各自只有一组值，不因页面而异。
- 组件只引用 `styles.css` 中的语义变量。不写死十六进制，不写死灰色阶。

## 材质与层次

材质是一条规则，不是一种风格：**玻璃标记"机器在报告自己"，不透明标记"这是你要逐字读准的数据"**。

| 档位 | 用法 | 理由 |
| --- | --- | --- |
| 真玻璃 `--material-glass` | 吸顶运行状态栏、浮层、tooltip、内联确认 | 底下真的有内容滚过去，模糊有收益 |
| 色调材质 `--material-chrome` | 侧栏、工具条、分段控件轨道 | 底下是纯色画布，模糊等价于纯色，白付合成层 |
| 不透明 | 所有内容面板、证据、消息、策略文本 | 逐字读准是底线 |

- 高度分三级 `--elevation-1/2/3`，**ring 优先**：深色模式收敛为纯 ring，因为深色上投影读不出来。浮层才用第二、三级。
- `@supports not (backdrop-filter)` 与 `prefers-reduced-transparency: reduce` 下，玻璃退化为不透明面。宁可失去玻璃，也不让正文压在糊掉的底色上。
- 侧栏与画布同色，靠发丝线分界；给侧栏换一个颜色会把窗口劈成"导航世界"和"内容世界"。

## 字体、层级与密度

- 正文优先 `Noto Sans CJK SC`，标题优先 `Bahnschrift`，数据优先 `JetBrains Mono`；均保留系统回退字体。动态数字使用等宽数字特性。
- 字号阶梯按 1.25 比例，token 化：caption 11 · label 12 · body 13 · body-lg 14 · h4 16 · h3 18 · h1 28 · display 34。
- **每个视图只有一个 h1**（`SectionHeader`）。空状态、加载态、错误态一律 h2；面板内嵌读数用 h3。
- 层级同时用字重与色阶，不靠字号单打：`value 650 / primary`、`label 600 / secondary`、`meta 400 / muted`。
- 以 4px 为基础间距单位。工作区主内边距 24px，面板 18px，列表项与控制区常用 12–16px，区块间距 16px。
- 圆角同心：嵌套圆角 = 外层 − 间隙。控件 7px、内嵌 8px、面板 12px、玻璃 14px。

## 信息架构

- 侧栏分三组，不是九个平级项：**值守**（待我处理／审批／任务／发送／反馈）· **配置**（策略／设置）· **系统**（健康／维护）。≤900px 隐藏组标签，保留发丝分隔线，分组在压缩形态下依然成立。
- 运行状态栏只报告，不带控件。四项读数是**指示灯 + 文字**：tone 只设 `color`，灯泡与光晕靠 `currentColor` 继承；灯泡 `aria-hidden`，因为文字已经说清楚。
- 设置页分两层：**外观与语言**（操作者自己的偏好，唯一可编辑的控件，永远可见，不参与搜索与筛选）在上，**产品字段只读目录**在下。
- 目录分四组：常规／高级／**策略字段**／诊断。只按可见性分组会让默认分组 69% 是策略拥有的卡片——操作者点进去看到的全是自己动不了的东西。策略字段单独成组；该组不是第二个编辑器，而是索引里写入路径属于策略页的那一部分，每张卡片的「在策略页修改」是链接而不是徒章。
- 卡片声称显示「当前值」就必须显示值。按会话设置的字段说明「按会话设置」而不是把会话数当成值；带 `status` 的状态对象渲染成状态标签而不是 JSON 串；API 以 null 列出的派生字段要回落到派生值，不能因为键存在就显示「未设置」。

## 可复用组件

| 组件 | 规范 |
| --- | --- |
| 按钮 | 最小高度 40px、水平内边距 12px、圆角 7px、13px 半粗字；危险等语义变体仅改变文字色。 |
| 确认按钮 | 两步：首次点击就地展开为「提示 + 确认执行 + 取消」，6 秒后自动解除，Escape 取消。禁用 `window.confirm`。 |
| 侧栏导航 | 行高至少 42px、水平内边距 10px；选中态是一个共享的 `layoutId` 药丸在项间移动，带 3px 青绿内侧标记。 |
| 列表行 | 最小高度 70px、内边距 12px、圆角 7px；选中时使用青绿边框与 3px 内侧标记；挂载时 4px 上浮 + 淡入。 |
| 分段控件 | 轨道圆角 12px、内距 4px、滑块圆角 8px（同心）；滑块是共享 `layoutId`，在选项间滑动；轨道宽度 `fit-content`。 |
| 状态标签 | 最小高度 24px、水平内边距 8px、胶囊圆角、12px 半粗字和等宽数字。 |
| 面板 | 18px 内边距、12px 圆角、发丝边框；工作区面板之间相隔 16px。 |
| 面板内读数 | `.signal-section`：h3 + 可选 fact-list + 列表或空态，用发丝线分隔，多个读数共用同一个面板框。 |
| 维护动作行 | `.rail-action`：无面板框，14px 标题、muted 说明、控件 `justify-self: start`。动作不是状态读数，所以不配面板。 |
| 待办决策入口 | 桌面最小高度 116px、内边距 16px、32px 数值；窄屏纵排时最小高度 88px。 |
| 状态提示 | 空态／加载态／错误态共用 `.empty-state`，标题为 h2。 |

## 动效

动效表达**空间连续性**，不做装饰。库负责挂载/卸载与布局（`motion` 的 `AnimatePresence` 与 `layoutId`），CSS 负责悬停、按下、颜色与焦点。

- 路由切换：140ms **纯透明度**淡入，不做位移。侧栏是高频控件，macOS 侧栏切页也不位移。没有退场动画——让上一屏多留 100ms 就会让点击感觉变慢，真正的交叉淡入需要两屏重叠。
- 设置页分组切换：`AnimatePresence mode="wait"`，退场 80ms、入场 180ms 交叉淡入，两个字段网格不重叠。
- 详情面板：200ms 6px 上浮 + 淡入，以选中项为 key。
- 列表项与命令结果：挂载时淡入 + 4px 上浮。
- `MotionConfig reducedMotion="user"`：系统要求减弱动效时丢弃位移、保留透明度，状态变化依然可见。
- 时长上限 300ms；曲线 `cubic-bezier(0.23, 1, 0.32, 1)`；只动 `transform` 与 `opacity`；禁止 `transition: all`。

## 状态与失败

- 每个可交互元素提供悬停、按下、键盘焦点和禁用状态。键盘焦点使用 2px 青绿轮廓，外偏移 2px。
- 每个命令都必须能说自己失败了：`failedCommandResult` 把失败渲染进结果面板，不留空白。UI 不得从乐观状态推断命令成功——清空所有者背景时删掉本地草稿而不是置空，失败时界面显示的是服务端真实内容。
- 空状态解释为什么空以及下一步做什么，不写"暂无数据"。

## 响应式

- 1180px 以下工作区多列布局折为单列；900px 以下侧栏改为顶部横向滚动导航（接管玻璃，状态栏转回不透明），工作区内边距改为 16px；560px 以下决策入口、数据区与偏好行改为单列。
- 表单输入、空状态和错误提示继续使用同一语义色体系，不因页面不同创建新的配色或尺寸。
