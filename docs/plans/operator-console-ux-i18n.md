# Operator Console 双语与可读性优化

状态：已完成（2026-09-23）

## 目标

在不改变本地、single-owner、Operator Query/Command 和显式发送边界的前提下，完成
Operator Console 的中英文支持、产品术语统一、渐进式帮助、信息密度和窄屏可用性优化。

本计划只改变 Console 的呈现与必要的稳定展示映射，不把技术标识、错误码、用户内容或
后端原始消息改写成业务结论，也不增加新的远程访问、自动发送或配置写入能力。

## 已确认设计

- 支持 `zh-CN` 与 `en-US`；首次默认中文，手动选择保存在浏览器本地。
- 使用 `i18next`、`react-i18next` 和模块化 Radix Tooltip。
- 系统生成的导航、状态、操作、策略字段、健康问题和命令摘要均可本地化。
- 中文主文案使用常见产品/技术词；原始枚举、ID、错误码和后端原文保留在技术详情中。
- 关键后果继续内联显示；概念解释使用支持 hover、focus 和 `Escape` 的帮助提示。
- Settings 使用分区、搜索、紧凑摘要和按需展开；原始 JSON、API 边界和审计元数据默认折叠。
- 修复长 ID/状态重叠、窄屏图标无文字、运行状态首屏占用过大和触屏帮助不可达问题。
- 保留现有一级导航、master-detail 工作流、主题和代码所有权边界。

## 术语原则

中文主界面优先采用以下表达，并在帮助或技术详情中保留括号内原词：

| 当前原词 | 中文主文案 |
| --- | --- |
| P2P | 单聊（P2P） |
| Owner | 所有者 |
| Product Policy Store | 运行策略库 |
| Policy Import Source | 策略导入源 |
| daemon | 守护进程 |
| tick | 调度周期 |
| checkpoint | 处理检查点 |
| readback | 发送回读 |
| fresh session rebuild | 新会话重建 |

未知枚举不得猜测翻译；显示本地化 fallback，并在技术详情保留原值。

1. **计划与边界** — 落本计划和当前 backlog 指针；不改运行代码。

7. **渐进披露与响应式** — 折叠命令/JSON 技术详情，加入复制操作，修复长文本、窄屏导航、状态条和键盘/触屏可达性。

## 验收标准

- 两种语言下九个一级页面、共享状态、空态、错误态和命令摘要没有硬编码的另一语言文案。
- 设置和策略字段通过稳定 catalog key 本地化；健康与推荐操作通过稳定标识本地化，未知值保留原文。
- 切换语言后无需刷新，选择在新标签页/重启浏览器后保留，日期和数字随语言变化。
- 帮助提示可由鼠标和键盘打开，可由 `Escape` 关闭；关键安全信息不只存在于 Tooltip。
- Settings 默认只显示一个分区，可搜索字段，并能展开查看来源、重启要求和写入边界。
- 原始 ID、枚举、错误码、后端消息和 JSON 可访问但不抢占主要信息层级。
- 390px 宽度下导航有可理解标签，运行状态不遮挡首要任务，长 ID 不与状态/时间重叠。
- 构建后的 `src/feishu_shadow_agent/console_static/` 与源码一致，打包入口和引用资产存在。

## 停止条件

- 本地化需要改写用户内容、模型输出或任意后端自由文本时，保留原文并只本地化外围标签。
- 新交互需要改变 Operator Command、发送、审批或策略写入语义时，停止并另行设计，不以 UI 优化带入。
- 某稳定标识不存在时，先使用显式 fallback；不得按英文句子内容进行脆弱匹配。
