# 08 · 扩样本复验与生产判定

状态：部分推进；无合格候选，生产判定为不推广。前置：会话 06 的 golden 有效；会话 07 已记录一个单变量候选或明确的未通过归因。

## 目标

用更多独立真实会话检验会话 07 的候选，决定是否形成一个受控的生产改动。没有候选或证据不足时，交付新的有效样本与归因结论，继续保留 S10。

## 阶段

1. **扩大有效样本。** 补至少三个相互独立的真实技术会话，由人确认目标时点可回答、事实在生产 Task Session 中可见，覆盖过度转交、遗漏、矛盾中的至少两类。将消息、配置、golden 与原始报告留在 ignored 目录；tracked 文档只写数量、标签审核和可复现条件。
2. **固定对照。** 用会话 07 的候选与 baseline，在旧有效样本和新增样本上固定 backend/model、reasoning、工具权限、配置、标签与 `repeat=1` 重跑。分别报告目标改善、重大错误、owner 转交、显式输入以及可取得的 token/费用/duration；对有争议标签先人工审核。
3. **条件推广。** 只有目标失败实质改善，没有新增重大矛盾或无依据扩展，也没有靠更多沉默/转交形成表面收益，且成本变化已说明，才做单一生产改动。为 prompt/schema 字段形状与安全、路由、审批契约补测试，验证并单独提交。无候选或无收益时提交不推广结论与下一假设，生产保持现状。

## 验收

生产候选需通过相邻测试、全量 pytest、Ruff、Pyright，以及受影响的前端/包检查；运行保持 eval-only，不调用 Dispatcher 或真实发送。`repeat=1` 的小样本不提供稳定性结论，报告要明确适用边界。只有已确认的回答失败得到实际处理才可关闭[当前待办](../post-mvp-backlog.md)中的 S10；未覆盖的失败继续保留。
